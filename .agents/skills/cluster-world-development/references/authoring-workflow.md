# Clusterワールド制作ワークフロー

## 1. 要件とプロジェクト条件

- Unity、CCK、Render Pipeline、対象プラットフォームのバージョンと制約を確認する。
- ワールドの目的、プレイヤーの開始位置、移動経路、見せたい視点、ゲームプレイ要素を整理する。
- 寸法・色・配置などの確定条件と、制作上の仮定を分ける。
- 既存Scene、Prefab、Material、Script、保護対象の変更ルールを調べ、作業範囲を決める。

## 2. Blenderでのアセット制作

- 先に必要なシルエット、寸法、部品構成、接続面を作り、装飾は後から追加する。
- Object名と階層を用途がわかる形にし、出力対象を明示する。
- FBXの単位、Forward/Up軸、適用する回転・スケール、原点の用途を決める。値は利用するExporterと受け取り側の仕様に基づく。
- 形状の接合境界を計算し、面の重複や表示面同士の近接でちらつきが起きないか確認する。
- 使用するMCPやExporterの機能を確認してから操作する。出力名の上書き、保存先、実際に出力可能なGeometry/Material機能を推測しない。

## 3. Unityへの受け渡し

- FBXをインポートし、Unity上のBoundsから実寸・位置・向きを設計値と比較する。
- Hierarchy、Mesh、Material、Shader、Prefab参照を確認する。期待したMaterialが適用されない場合、見た目を確認せずに完了扱いしない。
- GameObjectの責務を、表示専用、衝突、プレイヤー操作、環境背景などに分ける。必要なものだけColliderを設定し、Triggerと通常Colliderの用途を区別する。
- インポートしたモデルをシーンに置いた後も、接合、歩行面、頭上クリアランス、入口と通路の幅を確認する。

## 4. シーンとギミック

- 既存Sceneへの直接変更が不要なら、Preview SceneやPrefabで独立して検証する。
- Spawn Point、移動経路、床・壁境界、落下時の処理など、プレイヤーが移動するための前提条件を確認する。
- Scriptがオブジェクトを直接移動する場合、Colliderが移動を止めるとは限らない。トリガー、移動制御、境界判定を一連の動作として検証する。
- Editor用の生成・配置処理は、対象SceneとAssetを明示し、重複作成を避ける。入力不足や参照切れは例外・診断で明確にする。

## 5. 見た目と性能

- ShaderとMaterialが現在のRender Pipelineおよび配布先に対応することを確認する。
- Emissionは自己発光の見た目であり、周囲を照らすLightやBloomとは別の効果として扱う。
- 透明オブジェクトは描画順、重なり、Collider、両面表示を確認する。
- Light、影、透明オブジェクト、メッシュ密度を対象プラットフォームで確認し、背景オブジェクトに不要なColliderや影を持たせない。

## 6. 保存と受け渡し

- 元プロジェクトの一時ファイル、承認済みアセット、Unity `.meta`、生成物に関するルールに従う。
- シーンが参照するPrefab、FBX、Material、Texture、Scriptなど全依存アセットが存在し、Gitに必要な形で管理されていることを確認する。
- 作業後に差分を確認し、意図しないシーン全体の書き換えや無関係なAsset変更を除外する。
